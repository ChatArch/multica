Multica Desktop은 macOS, Windows, Linux에서 사용할 수 있습니다. Web 버전과 같은 계정 및 워크스페이스 데이터를 사용하지만 로컬 데몬을 자동으로 관리하고 워크스페이스별 탭을 따로 유지합니다.

## Desktop과 Web

| | Web | Desktop |
| --- | --- | --- |
| 여는 방법 | 브라우저 | 데스크톱 앱 설치 |
| 워크스페이스 탭 | 브라우저 탭 사용 | 워크스페이스별 독립 탭 모음 유지 |
| 데몬 | CLI를 별도로 설치하고 시작 | 로그인 후 앱이 자동으로 시작 |
| 업데이트 | 페이지 새로 고침 | 데스크톱 앱을 통해 업데이트 |

잠시 확인하거나 공용 컴퓨터에서 사용할 때는 Web이 더 편리합니다.

둘 다 동시에 로그인할 수 있습니다. 같은 Multica 서비스에 연결되어 있으면 표시되는 데이터가 공유됩니다.

## 설치

[Multica 다운로드 페이지](https://multica.ai/download)에서 운영체제와 프로세서 아키텍처에 맞는 설치 패키지를 선택합니다.

| 플랫폼 | 설치 패키지 |
| --- | --- |
| macOS | `.dmg` |
| Windows | `.exe` |
| Linux | `.AppImage`, `.deb`, `.rpm` |

설치 후 Web 버전과 같은 이메일로 로그인합니다. 로그인하면 Desktop이 내장 Multica CLI를 시작하고 로컬에 설치된 AI 코딩 도구를 감지합니다.

<Callout type="info">
Desktop 내장 CLI는 앱이 런타임을 관리할 때만 사용합니다. 터미널에서 `multica issue` 같은 명령도 실행하려면 [빠른 시작 2단계](/cloud-quickstart#2-컴퓨터-연결)에 따라 CLI를 별도로 설치하세요.
</Callout>

## 데스크톱 탭

Desktop은 워크스페이스마다 탭을 따로 저장합니다. 예를 들어 워크스페이스 A에서 이슈 세 개를 연 뒤 워크스페이스 B로 전환하면 B의 탭이 표시됩니다. A로 돌아오면 이전 세 탭이 그대로 남아 있습니다.

같은 리소스는 현재 워크스페이스에서 한 번만 열립니다. 탭은 순서를 바꾸고, 고정하고, 닫을 수 있으며 각각의 앞으로 가기, 뒤로 가기, 스크롤 위치도 유지됩니다. 현재 배포 환경의 앱 링크를 클릭하거나 붙여 넣으면 브라우저로 이동하지 않고 탭에서 바로 열립니다.

로그아웃하면 로컬에 저장된 모든 탭이 삭제되어 다음 로그인 사용자가 이전 계정의 페이지를 보지 못합니다.

## 내장 데몬

로그인하면 Desktop이 현재 Multica 서비스 전용 CLI profile을 만들고 이 profile로 데몬을 시작합니다. profile은 다음 위치에 있습니다.

```text
~/.multica/profiles/desktop-<host>/
```

터미널에서 사용하는 기본 profile을 읽거나 덮어쓰지 않습니다. 다른 데몬을 직접 동시에 시작하면 Multica에는 각각 별도 런타임으로 표시됩니다.

Desktop 설정에서 실행 상태와 로그를 확인할 수 있습니다. 도구가 감지되지 않으면 먼저 일반 터미널에서 실행되고 로그인되어 있는지 확인한 뒤 Desktop 데몬을 다시 시작하세요.

## Desktop 업데이트

자동 업데이트는 기본으로 켜져 있습니다. 앱이 백그라운드에서 새 버전을 확인하고 다운로드합니다. 다운로드가 끝나면 즉시 다시 시작해 설치하거나 다음 종료 시 설치할 수 있습니다. **설정 → 업데이트**에서 자동 확인을 끄거나 새 버전을 직접 확인할 수도 있습니다.

업데이트는 운영체제와 프로세서 아키텍처에 따라 배포됩니다.

- Windows arm64와 macOS x64(Intel)는 각각 별도 업데이트 소스를 사용합니다.
- 나머지 아키텍처는 기본 업데이트 소스를 사용합니다.
- 앱이 업데이트 소스를 자동으로 맞추므로 직접 선택할 필요가 없습니다.
- Linux 자동 업데이트는 `.AppImage`에서만 작동합니다. `.deb`와 `.rpm`은 새 설치 패키지를 내려받아 덮어씁니다.
- 자동 업데이트에 실패해도 다운로드 페이지에서 해당 설치 패키지를 받아 덮어쓸 수 있습니다.

## 자체 호스팅 인스턴스 연결

Desktop은 기본적으로 Multica Cloud에 연결됩니다. 자체 호스팅 인스턴스에 연결하려면 사용자 디렉터리에 `~/.multica/desktop.json`을 만듭니다.

```json
{
  "schemaVersion": 1,
  "apiUrl": "https://api.example.com"
}
```

`apiUrl`은 backend의 공개 주소로 필수이며 `http` 또는 `https`를 사용해야 합니다. 다음 두 주소는 생략할 수 있으며 Desktop이 자동으로 추론합니다.

- `wsUrl`: `apiUrl`의 프로토콜을 `ws` 또는 `wss`로 바꾸고 경로 뒤에 `/ws`를 추가합니다.
- `appUrl`: 도메인이 `api.`로 시작하고 세 구간 이상이면 `api.` 접두사를 제거합니다(`api.example.com` → `example.com`). 그렇지 않으면 `apiUrl`과 동일하게 유지합니다.

보통 `apiUrl`만 작성하면 됩니다. 추론 결과가 맞지 않을 때 명시적으로 덮어쓰면 됩니다. 일반적인 경우는 세 가지입니다.

- Web과 API가 서로 다른 도메인을 사용
- WebSocket을 별도로 배포
- 도메인이 접두사 제거 규칙을 만족하지 않음(`api.local` 같은 두 구간 도메인은 접두사를 제거하지 않음)

```json
{
  "schemaVersion": 1,
  "apiUrl": "https://api.example.com",
  "appUrl": "https://app.example.com",
  "wsUrl": "wss://ws.example.com/socket"
}
```

저장한 뒤 Desktop을 다시 시작합니다. 설정 파일이 존재하지만 JSON, 버전, URL이 유효하지 않으면 앱에 설정 오류가 표시되고 Cloud에 자동 연결되지 않습니다. 해당 파일을 삭제하고 다시 시작하면 기본 Cloud 설정으로 돌아갑니다.

<Callout type="warning">
Desktop은 브라우저와 실행 컴퓨터에서 모두 접근할 수 있는 주소에만 연결할 수 있습니다. 원격 자체 호스팅 인스턴스에 HTTPS가 없거나 WebSocket 프록시가 설정되지 않으면 Desktop이 연결되지 않습니다. 전체 설정은 [자체 호스팅 빠른 시작](/self-host-quickstart#3-접근-방식-선택)을 참고하세요.
</Callout>
